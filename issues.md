# Static Code Analysis - Identified Issues and Fixes

This document details the issues identified in `wildlife_sightings.py` using **Bandit**, **Flake8**, and **Pylint**. Findings are prioritized by severity (High and Medium severity first), along with root cause descriptions and resolution approaches.

## Issues Table

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| **B324: Weak MD5 Hash Usage** | Security (High Severity) | 15 | `hashlib.md5(observer.encode())` uses the MD5 digest algorithm which is cryptographically broken and vulnerable to collisions. | Passed `usedforsecurity=False` explicitly to indicate that the hash is used purely as a short non-cryptographic identifier, satisfying Bandit security standards. |
| **B608: SQL Injection via String Formatting** | Security (Medium Severity) | 9 | `conn.execute("INSERT ... VALUES ('{}', '{}', {})".format(species, zone, count))` constructs SQL dynamically via string interpolation, introducing critical SQL injection vulnerabilities. | Replaced string formatting with parameterized SQL query placeholders (`?`) passing parameters as a tuple: `conn.execute("INSERT INTO sightings (species, zone, count) VALUES (?, ?, ?)", (species, zone, count))`. |
| **W0102: Dangerous Mutable Default Argument** | Bug / Logic (Medium Severity) | 8 | `def logSighting(conn, species, zone, count, extras={})` uses `{}` as default parameter. Python binds default arguments once at definition time, causing `extras` to be shared across calls and mutate state unexpectedly. | Changed the parameter default to `extras=None` and initialized `if extras is None: extras = {}` within the function body. |
| **B101: Use of Assert Detected** | Security / Reliability (Low Severity) | 36 | `assert len(totals) == 3` is used for validation. Python's `assert` statements are stripped when running with optimizations (`-O` / `-OO`), bypassing the check entirely in production. | Replaced `assert` with explicit control flow and exception handling: `if len(totals) != 3: raise ValueError("Expected 3 species recorded in totals")`. |
| **W0621: Redefining Name 'conn' from Outer Scope** | Code Quality (Warning) | 8, 18, 26 | `conn` was instantiated at the top module scope and shadowed by the `conn` parameter in functions `logSighting`, `zoneSummary`, and `rarest`. | Removed the top-level global `conn` variable and created an explicit `init_db()` helper function called inside `main()`. |
| **E741: Ambiguous Variable Name 'l'** | Style / Readability (PEP 8) | 28 | Single-letter variable name `l` is ambiguous and easily mistaken for the numeral `1` or uppercase `I`. | Renamed variable `l` to a meaningful, descriptive identifier `rarest_row`. |
| **E225: Missing Whitespace Around Operator** | Style / Formatting (PEP 8) | 28 | `l=min(...)` omits spaces around the assignment operator, violating PEP 8 formatting conventions. | Added standard single whitespace around `=`: `rarest_row = min(...)`. |
| **E501 / C0301: Line Length Exceeded** | Style / Formatting (PEP 8) | 5, 9, 19, 27 | Multiple lines exceeded PEP 8's 79-character limit (and Pylint's 100-character limit), including database table creation and query strings. | Split long queries across multiple lines and extracted query strings into formatted variables. |
| **C0114 & C0116: Missing Docstrings** | Convention / Documentation | 1, 8, 14, 18, 26, 32 | The module and its functions lacked PEP 257 docstrings detailing their purpose, arguments, and return types. | Added comprehensive docstrings to the module and all functions (`log_sighting`, `observer_id`, `zone_summary`, `rarest`, `main`). |
| **C0103: Non-snake_case Naming Convention** | Convention / Style (PEP 8) | 8, 14, 18 | Function names `logSighting`, `observerId`, and `zoneSummary` followed camelCase rather than Python's standard `snake_case`. | Renamed functions to `log_sighting`, `observer_id`, and `zone_summary`, retaining legacy aliases (`logSighting = log_sighting`, etc.) for backward compatibility. |
| **R1705: Unnecessary 'else' after 'return'** | Refactor / Code Quality | 20–23 | In `zoneSummary`, `if row[0] is None: return 0 else: return row[0]` contained an unnecessary `else` block after an early return. | Removed redundant `else` and de-indented the terminal return statement: `if row[0] is None: return 0` followed by `return row[0]`. |
